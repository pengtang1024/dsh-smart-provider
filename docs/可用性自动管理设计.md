# 可用性自动管理设计（回归产品初衷）

> 状态：只读设计稿（task-90）。**不改任何代码/配置、不重启、不发真实请求、key 不打**。
> 用户初衷原话：**「我写这个插件本就是他们有很多问题，我希望这个插件能自动正确管理」**。
> 结论先行：**静态标注和人工探测永远追不上运行时变化——这是六类坑加 longcat 改名改价这第七类的共同病根。唯一可靠信号是用户自己的真实逐 hop 请求结果 + 上游模型清单，插件据此维护一张运行时健康注册表（单一真相源），cooldown / fallback / 选档 / 首屏标注全部读它，自动失效、自动恢复、自动感知资费变化，杜绝「标了永远不可用」和用户一次次来质疑。**

## 0. 病根与七类坑的共性（设计输入）

| # | 坑 | 静态标注为什么管不了 | 本设计的自动机制 |
|---|---|---|---|
| 1 | pi-ai compat（max_completion_tokens/max_tokens、developer/user）| 参数错让可用模型 400，静态表会误标"不可用" | 失败消息指纹识别 `PARAM_COMPAT`，判为配置问题不降健康，自动切 compat profile（§4） |
| 2 | 缺 x-opencode-session → MissingSessionID 400 | 与模型无关，静态表误伤 | `SESSION_HEADER` 类，补 header 不剔除模型（§4） |
| 3 | 单 provider 探测当全局（hy4flash-free 在 opencode 400、workbuddy 147 次成功）| 状态按 model 名全局标注，跨 provider 串味 | 状态键是 **(provider, modelId) 二元组**，绝不跨 provider 聚合（§2/§6） |
| 4 | 双源零成功≠不可用（workbuddy 不写账本）| 账本 0 就判废，是证据误读 | 账本 + 会话插件记录**双信号**；双源零样本 = `UNKNOWN`（低置信），不是 unavailable（§3.2/§9） |
| 5 | 虚拟副本泄漏（真身 + group='smart' 虚拟两条）| 静态表只看 model id，分不清真假 | 身份含 `isVirtual`，虚拟副本永不作 hop 候选（§2.1/§6.2） |
| 6 | 同名跨 provider 拼写差异（hy4-flash-free / hy4flash-free / hy4flash）| 一个 id 标注盖所有 | 精确拼写即独立条目；关联视图仅展示不参与判定（§6） |
| **7** | **旧 id 失效（改名/下线）+ 资费变化（free→计费）**（longcat 实测：旧名 400，新名 `longcat-2.5` 200 但改按订阅计费）| 静态表既管不了 id 过期，也管不了价格漂移，省钱账本静默失真 | `/models` 清单识别 `RENAMED` 自动关联新 id + **资费档次置信度**自动感知 free→metered（§4.3/§7） |

**一条底层原则**：插件不维护"哪个模型可用"的人工结论，只维护"从真实结果观测到的证据 + 置信度"，判定规则由代码执行。

## 1. 单一真相源：RouteHealthRegistry

所有下游读同一张运行时表，不再各维护静态表：

```
                       ┌──────────────────────────────────────┐
  真实信号（已有，零新增探测）│  RouteHealthRegistry（运行时 + 可选持久化）│
  ① cost.jsonl 每次 attempt │  key = provider::modelId（精确二元组）      │
  ② #recordHop 插件记录     │  value = {health, billingTier, confidence, │
  ③ llm/models-updated 事件 │            samples, failureKinds, relatedIds}│
  ④ 上游 /models 清单(复用)  └───────┬──────────────────────────┘
                                     │ 统一读取
        ┌────────────┬───────────────┼──────────────┬──────────────┐
        ▼            ▼               ▼              ▼              ▼
   cooldown      fallback       选档(routing)   首屏标注       省钱决策
   (已有)        (已有plan)     (过滤DEPRECATED) (诚实置信度)   (只信高置信free)
```

**为什么这样能消灭救火模式**：过去用户质疑一个→人工探测→静态标一个；现在每次真实请求都在自动更新注册表，用户不质疑也在管。人工标注从"结论"降级为"冷启动 seed"（§10）。

## 2. 数据模型（可编码字段）

### 2.1 身份键 `RouteKey`（解决坑 3/5/6）

```
RouteKey = {
  provider:      string,   // 实际 route：x-opencode-free / workbuddy / opencode-go
  modelId:       string,   // 精确拼写：hy4-flash-free ≠ hy4flash-free ≠ hy4flash
  providerFamily:string,   // 归一化厂家族：opencode / workbuddy（仅展示用）
  isVirtual:     boolean,  // group==='smart' 或 smart.listModels 产生的副本 → true
}
registryKey(key) = `${key.provider}::${key.modelId}`   // 状态粒度只到二元组
```

**硬规则**：
- **状态绝不按 `providerFamily` 或裸 `modelId` 聚合**——这是坑 3「单 provider 探测当全局」的直接防线。workbuddy 的 hy4flash-free 健康，不影响 opencode 的 hy4flash-free 判定，两者是两条独立记录。
- `isVirtual=true` 的条目**永不进入 hop 候选、永不写健康状态**（坑 5）。它们仍可在首屏显示（Smart Gateway 可见），但"可见 ≠ 可选为 hop"保持不变。

### 2.2 健康记录 `HealthRecord`

```
HealthRecord = {
  key: RouteKey,
  health: 'UNKNOWN' | 'HEALTHY' | 'DEGRADED' | 'DEPRECATED',
  billingTier: 'free' | 'metered' | 'unknown',   // §7
  confidence: number,        // 0..1，样本越多/信号越直接越高
  samples: { success:number, failure:number },  // 滑窗（默认最近 200 次，可配）
  failureKinds: Record<FailureKind, number>,    // 各类失败计数（§4）
  lastSuccessAt?: number, lastFailureAt?: number,
  relatedIds?: string[],     // RENAMED 关联的新/旧 id（§4.3）
  updatedAt: number,
}
```

**持久化**：内存为主；可选 `~/.dsh/smart-provider/health.jsonl`（追加写，复用 cost-meter 的批量刷盘模式），重启后重建。持久化是增强不是前提——冷启动从账本回放即可（§3.1）。

## 3. 自动获取（复用真实信号，零新增探测）

### 3.1 三个已有信号源

| 信号 | 位置 | 提供什么 |
|---|---|---|
| 逐 hop 成本账本 | `cost-meter.js` FIELDS：timestamp/actual_provider/actual_model/failure_code/failure_message/estimated_cost_usd | 每次 attempt 的成功/失败码 + 去敏 400 正文 + 成本（**主信号源**）|
| 会话 hop 记录 | `adapter.js #recordHop` → `plugin:dsh-smart-provider/hop-selected` | 选了哪个 hop、失败码、accountId（会话级证据）|
| 模型目录变化事件 | `llm/models-updated` + `llm/adapters-updated`（P1 已用）| 上游端点/模型清单变化时触发重新评估（**自动恢复触发器**）|

**落地**：adapter 在 `#recordCost`（adapter.js:293）写账本时，**同一处**同步更新 `RouteHealthRegistry`（内存）；不需要新发任何请求。历史账本在冷启动时回放一次即可建立基线——8700+ 笔 cost=0 的 x-opencode-free 记录会自动得出 HEALTHY + free(高置信)，省钱链天然保住。

### 3.2 双源证据规则（杜绝坑 4）

- `evidence(provider, modelId)` = 账本样本数 + 会话记录样本数（**按二元组分别计，不合并跨 provider**）
- **双源零样本 → `health=UNKNOWN`，不是 unavailable**。UI 显示"暂无数据"，绝不显示"不可用"。
- **只有一源有成功样本即判 HEALTHY**（如 workbuddy 不写账本但会话记录有 147 次 completed → HEALTHY，账本 0 不算废）。
- 判定置信度 = f(样本数, 信号直接度)：真实成功样本 > 会话记录 > 账本零推断；零样本 confidence=0。

### 3.3 上游 `/models` 清单（解决坑 7 的 id 清单信号）

- DSH 已有模型发现能力（`dsh-llm-pi-ai` 注册 `registerModelDiscovery`，其 `discovery.ts` 的 `listingUrl` 会按协议拼 `/models`）。设计复用该 API 拉取当前 id 清单，**不自己发裸 HTTP**。
- 用途二：① 判断某 id 是否还在清单里（缺失 = 改名/下线信号）；② 找出语义相近的新 id（改名映射）。
- **未验证**：DSH 的发现 API 是否已对 smart 内部暴露、`/models` 是否含价格字段——落地先用只读探针确认；拿不到则 §7 资费感知降级为仅靠账本（confidence 封顶 medium），id 清单信号标未验证。

## 4. 自动判定规则（代码可执行，优先级从高到低）

输入：`normalizeFailure()` 已产出的 `{code, message}`（adapter.js:54-77）+ sanitized 400 正文（adapter.js:88 起）+ 上游 id 清单。

`classifyFailure(failure, ctx) → {kind, affectsModelHealth, retryable, suggestedAction}`

| 优先级 | FailureKind | 可编码触发条件（message 为去敏正文） | 对健康的影响 | 处置 |
|---|---|---|---|---|
| P0 | `SESSION_HEADER` | `/MissingSessionID\|x-opencode-session/i` | **不影响** | 补 header（pi-ai 已对 opencode 系自动注入；自定义 route 需声明 headers），短冷却重试 |
| P0 | `PARAM_COMPAT` | `/max_completion_tokens\|max_tokens\|developer role\|invalid.*parameter.*(400)/i` | **不影响** | 该 route 切 compat profile（supportsStore/developerRole/maxTokensField），不剔除模型 |
| P1 | `RENAMED` | code∈{404,UNKNOWN_MODEL} 且 id 清单无该 id、但有高相似新 id | 旧 id→DEPRECATED，新 id→新增候选 | 自动关联（§4.3），**触发资费复核** |
| P1 | `OFFLINE` | code∈{404,UNKNOWN_MODEL} 且 id 清单无相近 id，连续≥N 次 | →DEPRECATED（可恢复）| 低频复核（§5） |
| P2 | `QUOTA` | code∈QUOTA_CODES（402/quota/额度）| **不影响模型健康**（账号级）| 沿用现有 cooldown（30min） |
| P2 | `RATE_LIMIT` | code∈RATE_CODES（429）| 不影响 | 沿用现有 cooldown（1min）|
| P2 | `AUTH` | code∈AUTH_CODES（401）| 不影响模型（账号/凭据问题）| 账号级冷却 |
| P3 | `SERVER_JITTER` | code∈JITTER_CODES（5xx/timeout/transport）| 连续超阈值→DEGRADED | 短暂冷却（现有 5s）|
| P4 | `UNKNOWN` | 以上都不命中 | 记 evidence，不改 health | 累计样本后再判，低置信诚实呈现 |

**关键纠偏**：坑 1/2 的 400 在旧逻辑里 `inferCodeFromMessage` 会把 `400` 归到 SERVER（因为末尾 `return 'SERVER'`），进而触发冷却、甚至被人工误标 unavailable。新规则把"参数/请求头类 400"从健康判定里**剥离**——这是自动管理最重要的正确性修复。

### 4.1 改名识别与资费复核（坑 7）

`resolveModelId(requestedId, currentIdList, registry)`：
1. 若 requestedId 在 `/models` 清单中 → `use`。
2. 若不在，计算与清单 id 的相似度（去后缀 `-preview-free`/`-free`、`-`与无分隔归一、小写）：
   - **极高相似**（归一后相等，如 `longcat-2.5-preview-free`→`longcat-2.5`）→ `remap`：新 id 加入候选，旧 id 标 DEPRECATED，`relatedIds` 互相记录，**强制资费复核**（因为改名常伴改价）。
   - 中等相似 → 不自动 remap，标 `UNKNOWN` 并在首屏诚实提示"疑似改名，待确认"（低置信不自动改路由）。
   - 无相似 → `OFFLINE` 判定。

## 5. 自动失效与恢复（状态机，杜绝永久拉黑）

```
              ┌──────────────────────────────────────────┐
              │  任何状态 + 新成功样本 → HEALTHY（自动恢复）│
              └──────────────────────────────────────────┘
UNKNOWN ──成功样本──▶ HEALTHY ──连续失败率>阈值──▶ DEGRADED
   │                    │                            │
   └─双源零样本(保持)    ├─QUOTA/RATE/参数/头(不变)    └─恢复成功→HEALTHY
                        └─RENAMED/OFFLINE──▶ DEPRECATED
DEPRECATED ──① 上游 /models 清单该 id 重新出现（llm/models-updated 触发）
            ──② 用户配置变更（loader/volatile-update）
            ──③ 真实流量自然 fallback 到它并成功
            ───────────────▶ HEALTHY   （三条恢复路径，绝不永久）
```

- **DEGRADED 不剔除**：仍可作 hop，只是排序降权；真实 fallback 到它若成功即恢复。
- **DEPRECATED 仍保留在候选池**（不删），排序最低 + 首屏标"曾失效/待复核"；恢复靠三条自然路径，**不靠玩家点"恢复"、不靠人工改静态表、不靠主动探测**。
- 冷却时长沿用现有 `cooldownFor`（adapter.js:99-115），健康状态与冷却是**两个正交维度**：冷却是"这个账号暂时别打"，健康是"这个模型/route 还行不行"。

## 6. 跨 provider 同名处理（解决坑 3/5/6）

### 6.1 判定与状态：严格按二元组

- `workbuddy::hy4flash-free` 与 `opencode-go::hy4flash-free` 是两条独立 HealthRecord。
- 任何"某 id 不可用"的判定**只作用于该 (provider, modelId)**，不得推导到同名的其他 provider（直接封死坑 3）。
- `providerFamily` 只用于 UI 分组展示，不参与 `isCandidate()` / `classifyFailure()`。

### 6.2 虚拟副本隔离（坑 5）

- `isVirtual=true`（group==='smart'）的条目：**不入注册表、不作 hop、不参与 fallback**；只在首屏以 "Smart Gateway 虚拟模型" 标签显示。
- 校验：生成 hop 时过滤 `isVirtual`（现有 `discoverAutoChain` 已过滤 provider==='smart'，本设计把它推广到所有虚拟来源）。

### 6.3 关联视图（不参与判定）

- 三个拼写（hy4-flash-free / hy4flash-free / hy4flash）可在首屏"同一模型的不同 route"分组展示，但每条的健康/资费独立。分组是给人看的，机器判定只看精确二元组。

## 7. 资费档次自动感知（解决坑 7 的 free→计费）

**问题**：longcat 新名可用但不再免费。若还按静态 price=0 当"免费首跳"，省钱账本会静默失真。

**资费判定（带置信度，不靠人工改 pricing）**：

| 信号 | 判定 | 置信度 |
|---|---|---|
| 上游 usage 明确 `cost=0` 且 `billing_source` 为免费/试用（本机直连探针见过该字段；DSH 是否透传**未验证**）| `free` | high |
| 上游 usage `cost>0` 或出现额度扣减标记 | `metered` | high |
| 我方账本 `estimated_cost_usd=0` 连续 N 次（N≥20）且无反证 | `free` | medium（这是我方定价表算的，不是上游真实价）|
| 仅有 pricing.json `price=0` 标记，无真实样本 | `unknown` | low（**不冒充免费**）|
| 改名/改价事件（RENAMED）触发 | 强制复核，旧置信作废，重新采样 | — |

**省钱决策接线**：
- 只有 `billingTier=free 且 confidence≥threshold` 的条目才可作为"免费首跳"的强保证。
- `unknown` 条目照常参与路由，但首屏标注"资费未确认"，不宣称省钱。
- **向后兼容铁律**：当前 x-opencode-free/hy4-flash-free 有 8700+ 笔 cost=0 账本 → `free(high)`，继续当免费首跳，auto[0] 不变。新机制绝不把高置信免费条目降级。

## 9. 接口契约（新增 lib/availability.js，纯函数）

## 10. 静态 FREE_MODEL_STATUS 迁移路径（何时能删）

现状 `client.js:353-361` 人工表（7 条，含注释"双源零成功"等已被证伪的依据）。迁移三步：

1. **阶段一（seed）**：静态表降级为冷启动 seed——仅在 registry 无该条目样本时提供初始提示，且明确标"未复核"。不再作为最终判定。
2. **阶段二（覆盖）**：registry 的高置信判定（≥N 样本或 /models 清单确认）覆盖静态表；静态表里那 5 条标 `unavailable` 的条目，若双源零样本，自动改为 `UNKNOWN`（诚实——"双源零成功"已被证伪，不能在产品里继续当不可用）。
3. **阶段三（删除）**：**删除条件** = ① 所有首屏展示条目都有 registry 状态（运行时覆盖率 100%）；② 低置信条目有 `UNKNOWN` 诚实兜底；③ 改名/资费复核路径上线。满足后静态表不再提供任何信息，可整表删除。

**明确**：不设"到日期自动删"，按覆盖率达标删——避免为删而删再引入误判。

## 11. 诚实边界（DSH 现状做不到 / 未验证）

| 项 | 状态 | 降级路径 |
|---|---|---|
| 上游 usage.cost / billing_source 透传到 DSH TokenUsage | **未验证**（直连 HTTP 响应有此字段，DSH adapter 是否保留未知）| 拿不到则资费置信封顶 medium，仅靠我方账本 |
| `/models` 是否含价格字段 | **未验证** | 只能拿 id 清单做改名判定，价格靠账本 |
| 改名映射（无官方 API）| 只能相似度推断 | 极高相似才自动 remap，中等相似标 UNKNOWN 待确认 |
| "同一模型"跨 provider 的语义映射 | 无可靠来源 | 只按精确二元组判定，关联视图仅展示 |
| 双源零样本 | 无法判可用/不可用 | 一律 UNKNOWN，不自动剔除、不标废（不违反"不靠双源零成功判不可用"）|

**绝不做**：不编造置信度数字、不把 0 样本说成 0% 可用、不把虚拟副本算进成功率、不因单 provider 400 标全局不可用。

## 13. 向后兼容（硬约束）

- 省钱链：自动机制只**增强**判定，不改动 auto 链生成与 cooldown 时长；高置信免费条目继续当首跳，cost=0 账本不回归。
