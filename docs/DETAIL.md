# 智能模型路由（Smart Provider）

一个注册为 `smart` 路由的元提供商。它本身不调用任何大模型 API —— 而是在你**已配置的 DSH 供应商路由**之间按序尝试，选取第一个能响应的路由。它是**通用智能路由**，不是省钱工具：四个目标是省钱 / 高性能 / 高能力 / 复合（智能），代码默认中立（均衡权重 .25），省钱优先是用户自己的 config 选择。

**当前状态：插件已安装并启用，已设为默认模型，插件状态 ACTIVE。** 智能路由默认生效；省钱链路、配置页真读写、P1（资源自适应 / 中立默认 / 动态链）、P2（两层智能路由，默认启用、中立等权，可显式关闭）、三层健康自动管理（默认开启）均已落地并独立验收。路由顺序随你的实时注册表与配置决定，本文档不写死具体数字。

## 功能特性

- **默认生效的智能路由。** `smart/auto` 是默认模型，已在真实会话中验证选路与回退。内置链表刻意为空，未配置时由 `discoverAutoChain()` 从实时 DSH 注册表生成中立 `auto` 链（按 provider / model 名排序，不内置任何具体用户的模型）。
- **省钱链路（用户可选，不是默认）。** 免费路由 `x-opencode-free`（`hy4-flash-free`）由 `registry/custom-routes.user.yaml` 的 `tier: free` 自动排在链首，真实账本中该路由每笔 `estimated_cost_usd=0`（已核对 213+ 笔）；遇到 402/配额错误回退到付费路由。2.3.0 统一免费判据（`free-signal-v1`）：名字含 `free`、`priceMultiplier=0` / `costModel=free` / `priceTier=free` 只是「默认免费（未实测）」的弱信号 / 用户声明，可用于收录与排序、显示「可能免费（未实测）」，不写 L1 `billingTier=FREE`，且会被 probe `metered`、正成本账本或付费 `billingSource` 推翻；`unknown` 不阻断弱信号，估算零价不算证据，设置页可直接改账号价格倍率。免费标签分实测 / 声明 / 未实测三档；账号倍率 0 属声明级，可被实测付费证据推翻；当前部分路由 probe 多为 `unknown`，根因仍是【待验证】，不据此宣称探测已能下结论。
- **账号池（多账号 = 池化）。** 模型与账号是两个独立维度。每一跳的模型映射到一个账号池（`{id, provider(路由), credentialRef, models[]}`）；优先选择本跳路由上的健康账号，再按最少使用排序；转向下一个模型前会尝试该模型的每一个健康账号。DSH 每条路由只绑定一个 key，因此第二个账号 = 第二条 provider 路由。可选 `accounts` 数组；不配置时行为与旧版逐字节一致。
- **账号级冷却。** 冷却以 `accountId` 为键，而非 `provider/model`。某个账号遇到 402 或配额错误只冻结该账号，同模型的其他账号继续服务。
- **三层健康自动管理（默认开启）。** 模型层（`lib/availability.js`）、账号层（`lib/account-health.js`）、拓扑层（`lib/provider-topology.js`）分开记账，共享同一份注册表；参数不兼容或缺少 session 头的 4xx 不连累模型健康；账号冷却到期只进入 `HALF_OPEN`，需要一次真实请求成功才恢复 `ACTIVE`（没有证据就没有恢复）；自带账号池的路由不会被再套一层账号池（凭结构化证据判定，无 provider 名字白名单）。用 1 token 的真实探测替代“按模型名猜免费/付费”，结论 `unknown` 永不阻断选路。**冷启动水合（1.2.0）**：激活时由 `lib/health-persistence.js` 纯读重放 `cost.jsonl`（L1 逐行走 `updateHealth()`、L2 交给 `rebuildFromLedger()` 后合并进适配器持有的同一注册表对象）与 `probe-cache.jsonl`（探测结论回灌 L1），重载插件不再清零已证明过的健康/计费证据；读取上界是 4 MiB 尾部字节窗 + 5000 行（常量，不可配），只读、缺失/损坏/半行/目录不存在均不抛错，且从不覆盖更新的实时证据（按时间戳比对）。关闭方式：`health: false`、`health.enabled: false` 或 `ranking.health.enabled: false`，关闭后逐字节回 legacy（此时也不水合、连文件都不打开）。
- **仅在建立前回退。** 一旦发出任意文本、推理或工具调用块，响应即提交 —— 不会回退你已经看到的 token；`ABORTED` 永不回退。
- **逐次尝试的会话记录。** 每次尝试写成一条可忽略的插件记录 `plugin:dsh-smart-provider/hop-selected`，载荷为
  `{event:'smart/hop-selected', hopIndex, provider, model, accountId, failureCode, at}`。
  这是 `smart/hop-selected` 的安全仓库外扩展方式：直接发未知事件类型会让会话持久化拒绝恢复日志。
- **账号择优 ranking（P1，默认启用、中立等权）。** 成本 / 速度 / 等级 / 负载四因子评分；`balanced` 中立默认（.25），不偏向省钱 / 速度，`cost-first` 等是显式选项；显式 `enabled:false` 时保持旧行为（路线优先 + 最少使用）。速度因子按「实测优先 → `speedTier` → 中性回退」取值：优先用本次会话账本的真实延迟证据（`ttft_ms` / `tokens_per_second`），无实测再选手填档位。
- **延迟度量（cost.jsonl）。** 每条成本记录可携带 `started_at` / `first_token_at` / `finished_at`（ISO 时间戳）、`ttft_ms`、`duration_ms`、`tokens_per_second`；缺数据时整段不写，旧行（无这些键）聚合行为不变。ranking 与成本页都能消费这些派生指标。
- **查询报表（`scripts/query-cost.mjs`，1.2.0 起追加两段）。** 花费汇总与分组花费表保持不变，其后追加：**failure rate**（每组的 `failed / calls`；只有真的写了 `failure_code` 的行算失败，缺失或空串算成功）与 **latency**（`ttft` 均值、nearest-rank `p50`、ttft 样本数、`tok/s` 均值、tps 样本数）。**缺延迟键的老行不计入延迟统计**（绝不当 0ms：一个 0 会静默拉低均值、报出从未观测到的“变快”），`ttft_ms` 真为 0 仍是合法样本；样本 <3 打 `*`，无样本打 `-`，整次选择无样本打诚实空态文案；垃圾值（字符串、`NaN`、`Infinity`、负 ttft）进不了统计，报表里永不出现 `NaN`。
- **定价是用户数据。** 随包默认表 `lib/pricing.json` 只含零价免费档声明（当前 4 行）；真实单价经 `DSH_SMART_PRICING_FILE` 或 `registry/pricing.user.json` 导入（解析顺序：环境变量 → 用户表 → 默认表）。无表可查的模型返回 tier 粗估（`known:false` / `estimated:true`，金额恒 0）；作者真实价格导出保留为 `lib/pricing.example.json` 示例，不在默认加载路径。
- **两层智能路由 routing（P2，默认启用、中立等权）。** `lib/routing.js` 四个纯函数：请求分类、模型位置标签推导、候选层选择、预设解析。默认启用（`enabled:true` / `balanced` / 四因子 .25）；显式 `ranking.routing.enabled=false` 时逐字节走 legacy。8 种策略预设：`balanced` / `cost-first` / `speed-first` / `reasoning-first` / `longctx-first` / `vision-first` / `legacy` / `custom`。位置标签从模型 catalog 自动推导（reasoning / contextWindow≥200000 / 输入含 image / tool!==false / 通用），可用 `positionOverrides` 手填纠正 —— **对象形态 `{tags:[...]}` 与数组形态 `[...]` 都受支持**（此前只读 `.tags`，README 自带的数组写法静默无效），两者都做白名单过滤后与自动推导结果**保守合并**（不是替换）；`tierLimit` 的 `-1` / `0` / `NaN` 回落默认 2 层、小数向下取整。层一无匹配时 relax 不阻断请求，但告警从“只报任务类型”升级为可行动诊断：首行字面不变（grep 兼容），续行给出缺失标签、每个候选路由实际携带的标签、该标签为何无法自动推导、可复制的 `positionOverrides` 两种写法、以及 `tierPolicy` 不能凭空造标签的边界说明。配置错误只会 WARN 并回退 legacy，不会崩溃。
- **「花费与健康」Tab 真账（设置页共三个 Tab：总览 / 路由设置 / 花费与健康，2.2.0 由四 Tab 合并）。** 该页通过 `@Remote` 服务 `smartProvider.cost()` / `costDetail()`（`lib/remote.js`）读取 `lib/cost-stats.js` 对真实 `cost.jsonl` 的聚合（总花费 / 免费 / 付费 / 失败 / 按 provider），不是估算占位；逐笔明细带固定 6 个延迟字段与 ttft / tok/s 两列，成本趋势按**本地自然日**分桶；设置页同时展示来自 pi-ai 的真实 provider / model 与凭据名。

## 安装

安装单位是组合包：`dsh plugin --profile <profile> add link:<本包目录>`（或插件页「添加插件」）会把依赖、`dsh.profile.bundles` 选中项与 patch 行一起处理。本地目录保存为 `link:`，源码改动即时生效、无需重装；卸载用 `remove @local/dsh-smart-provider`。安装后 host 日志应出现 `registered smart adapter with N chain keys` 与 `discovered N neutral auto hop(s)`。

运行时只硬依赖 `llm` 服务：`sessions` / `commands` / `credentials` 通过 `ctx.get()` 按需读取，缺失时仅对应能力降级，不会让插件加载失败。所有 DSH 包经 `lib/dsh.js` 的 manifest 锚点解析，因此 `link:` 进任意 profile 都能工作。

## 配置方式

`chains`、`accounts`、`ranking`、`ranking.routing`、`health` / `ranking.health` 均为 volatile 配置，设置页改完即时生效，无需重启。健康层可调 `health.accountHealth`（半开许可数 / 退避倍数 / 冷却上限）与 `health.topologyOpts`（拓扑证据），`health.virtualProviders` 追加虚拟路由（`smart` 永远在内）。routing 配置嵌在 `ranking.routing` 下（`schema.js` 的 `routing` 字段），字段：`enabled` / `strategy` / `tierPolicy` / `weights` / `positionOverrides` / `tierLimit` / `longContextTokens` / `dynamicAuto`。未配置时代码路径完全不运行；显式 `chains` 键与 `*` 始终优先于 `dynamicAuto`，老配置不会被动。账号池 `accounts` 每项形如 `{id, provider, credentialRef, models[]}`，省略时按旧 per-hop 模式运行。自建路由只在 `registry/custom-routes.user.yaml` 声明（`credentialRef` 只放引用名，绝不放明文 key）。

详细设计依据父工作区的文档：`meta-provider-设计方案.md`、`多账号池设计方案.md`、`方案盲点审查.md`、`可用性自动管理设计.md`、`账号池自动管理深化设计.md`、`落地规格.md`。验证入口见包根目录 `npm test`（`scripts/run-tests.mjs`）：门禁自动发现 `test/*.test.mjs` 并全部执行（**新增测试文件无需注册**），并带发现守卫 —— `test/` 下存在未被执行的 `.mjs` 就非 0 退出并点名。当前全套（`node scripts/run-tests.mjs`，需 Electron 的 Node）19 个测试文件 / tests 254 / pass 254 / fail 0、`node scripts/run-tests.mjs --unit`（14 个纯逻辑测试文件）tests 207 / pass 207 / fail 0（均为 2026-11-26 实测，退出码 0）。探针 TTL 用例用注入时钟推进过期（不再用 5ms 真实 TTL 竞速），TTL 判定不依赖真实时序；两套门禁并发跑也不会再偶发假红，仍建议串行便于读数对账。

## English summary (secondary)

A meta-provider registered as the `smart` route, currently **installed and enabled** as the default model. It is a general intelligent router (cost / speed / capability / composite), neutral by default in code; saving-first is an opt-in user config. Verified: `smart/auto` in real sessions, `x-opencode-free` free first hop (cost=0, 213+ real ledger rows) with 402→paid fallback, a settings page with real pi-ai resources and an `@Remote` real-ledger cost tab, P1 resource adaptation, P2 default-on, neutral-equal-weight two-layer routing (explicit `ranking.routing.enabled=false` returns byte-for-byte legacy, 8 presets), latency metering in `cost.jsonl` (`started_at`/`first_token_at`/`finished_at`/`ttft_ms`/`duration_ms`/`tokens_per_second`, omitted when data is missing) feeding a measured-first speed factor, default-on three-layer health auto-management (model / account / topology layers with half-open recovery, structural aggregator detection, and a 1-token free-vs-metered probe; explicit opt-out returns byte-for-byte legacy), cold-start hydration that replays cost.jsonl / probe-cache.jsonl into the same L1/L2 registries (read-only, 4 MiB / 5000-line tail window, tolerant of missing/corrupt/partial rows, never overwriting newer live evidence), an actionable relax diagnostic (missing tag, each candidate's real tags, copy-pasteable positionOverrides in either documented shape, never blocks), a query-cost report with appended failure-rate and latency sections (legacy rows without latency keys excluded, never counted as 0ms), and a test gate that auto-discovers every test/*.test.mjs plus a discovery guard that fails when a file under test/ would never run. Pricing ships only zero-price free-tier declarations; real per-token prices are user data imported via `DSH_SMART_PRICING_FILE` or `registry/pricing.user.json`, with unknown models resolved to a zero-amount tier estimate. A real end-to-end run through `smart/auto` in a minimal headless profile answered twice and wrote 5 ledger rows across two live routes with complete usage and known pricing. Runtime contract: only the `llm` service is required; DSH packages resolve through manifest anchors so a linked bundle loads in any profile. See the package README for the full configuration and verification commands.
