## 0. 一句话结论

**代码里已有一套完整、可复用的「免费/付费最小探测」框架**（Host `lib/probe.js` + `@Remote probeModels` + 客户端 `runProbe`/`probeVerdicts`，结果带 7 天 TTL 缓存并写入 L1 健康注册表），**免费模型判定也有统一的 `freeSignal()` 契约**；因此"挑一个免费模型探一次"的技术动作**现成可复用、改动很小**。但**"据此判断这台机器的本地模型分组"缺少最关键的一环**：代码里没有任何"分组由探测结果推导"的字段或算法——`group` 是 `session.modelCatalog()` 给出的静态 provider/route id（`client.js:2959`），而 `derivePosition()` 推导的是模型能力定位标签（reasoning/longctx/…，与分组无关）。**判定标准（探到什么算哪个分组）必须先由用户定义，否则这条思路没有落地目标。**

### 1.2 结果数据结构

- **单次结果**（`lib/probe.js:199-202`）：`{ verdict, evidence, ok, probedAt, cost }`；`probeModels()` 对外返回 `{ results: [{provider, model, verdict, evidence, ok, cost, probedAt}], probedAt }`（`lib/probe.js:263-265`，schema 在 `client.js:300-315`）。
- **缓存行**（`lib/probe.js:204`）：`{ provider, model, verdict, evidence, ok, probedAt, cost }`，追加到 `probe-cache.jsonl`。
- **verdict 语义**（`lib/probe.js:17-23,88-103`）：`free` = HTTP 成功且 usage cost=0 且有 free/trial/bonus/allowance 计费源；`metered` = cost>0 或 paid/meter/credit 计费源；`unknown` = 错误 / 无 usage / cost=0 但无计费源证据。**`unknown` 永不作结论、也不挡弱信号**（"不能挡"规则）。
- **TTL**（`lib/probe.js:37-46,137-150`）：`free`/`metered` 7 天；`unknown` 10 分钟（失败也缓存以防重复烧钱，但 `peek()`/`isEvidence()` 只放行实测结论，`157-159,277-280`）。

## 2. 免费模型判定方式

统一契约是 **`freeSignal()`**（Host：`lib/free-policy.js:84-132`；浏览器内联镜像：`client.js:90-137`）。等级阶梯 **measured > declared > weak > none**（`lib/free-policy.js:17-18`）：

| 等级 | 触发证据 | 代码位置 |
|---|---|---|
| measured | `probeVerdict === 'free'`；真实价格表行 input/output 均为 0（`known:true, estimated:false`）；free 计费源账本 | `free-policy.js:95-116` |
| declared | `priceMultiplier/multiplier === 0` 或 `costModel === 'free'`（用户声明） | `free-policy.js:89-94,117-122` |
| weak | provider/model/name/group 含字符串 `free`（大小写不敏感）；`priceTier === 'free'` | `free-policy.js:26-32,123-129` |
| none | 付费硬证据（`probeVerdict==='metered'` / 正价格 / 付费账本）或无信号 | `free-policy.js:97-104,130-131` |

- **价格表**：`lib/pricing.js` 的 `priceForExact()`（`:182`）；随插件发布的是 `lib/pricing.json`，**只有 2 条免费零价行**（`x-opencode-free/hy4-flash-free`、`x-opencode-free/hy4flash-free`），真实价格属用户数据不随插件发布（文件 `_note`）。
- **客户端挑选"可能免费"**：`isPossiblyFree()`（`client.js:928-956`）先读 Host 的 tuple 级 `freeSignal`（`tupleScope()` `client.js:155-172`），否则本地跑 `freeSignal()`；`maybeFreeModels = nonVirtualModels.filter(isPossiblyFree)`（`client.js:957`）。自动探测候选正是从这里出（`client.js:2897-2915`）。
- **能否可靠挑出一个免费模型？** **弱信号层面能挑出"候选"，但"确认免费"高度依赖探测/账本/真实零价表**：真实免费模型历史上名字都含 `free`（`client.js:928-948` 注释），但 `flash`/`trial`/`preview` 不算免费信号（`free-policy.js:27-29`）。因此"用 free 名字挑一个"是启发式，可靠性有限；若要求"确实免费再探"，须复用 `probeVerdict` / `measured` 证据，而这又需要先探一次——存在鸡生蛋问题（见 §5）。

## 3. "本地模型分组"字段的来源与含义

**代码里没有名为"本地模型分组"的字段或机制。** 与"分组"相关的有三条线，需澄清用户指哪一条：

1. **`group`（最可能是用户口语所指的"每台机器/通道"）**：`client.js:2958-2960` 从 `session.modelCatalog().value.groups[].models[]` 归一化出 `{id, name, group: g.id}`。这里的 `group` 即 **modelCatalog 的分组 id = provider/route id**（`lib/probe.js` 里作为 `provider` 使用；`client.js:1057/1644` 用 `${group}/${id}` 拼 key）。它是 **pi-ai 静态目录给出的、不可由探测动态推导**；`group === 'smart'` 是虚拟副本需排除（`client.js:1171-1172,945`；`docs/可用性自动管理设计.md:175`）。
2. **`derivePosition()` 的"定位标签"**（`lib/routing.js:205-224`）：reasoning/longctx/vision/tool/general（+手填 thrifty/swift），由 catalog 能力字段推导，运行期用于层一选档（`lib/adapter.js:644-688`）。**这是"模型定位"，不是"分组"**；`docs/现状调研报告-模型定位只读展示.md` 即此需求的现状报告。
3. **`provider-topology.js` 的拓扑分类**（`AGGREGATOR/DIRECT/UNKNOWN`，`:27-30,115-...`）：按结构化证据判断某 provider 是否内部池化账户——这是另一维度的"分组"，与资费探测无关。

**结论**：用户说的"判断这台机器的本地模型分组"，在当前代码中**没有对应字段**；若指 `group`（provider/route），它来自静态目录、不随探测变化；若指一个新的"免费档/付费档"分组，**需要新算、新存**，现有代码里没有可直接复用的分组推导函数。

## 4. 可行性评估：可复用 vs 需新增

### 现成可复用
- **探测框架**：`lib/probe.js` 全套（发请求、verdict、TTL 缓存、L1 写入、invalidate、peek、`maxPerCall=3` 防涝）。
- **免费判定**：`lib/free-policy.js:freeSignal()` + `lib/remote.js:projectFreeSignal()`（已把 probe verdict 纳入证据）。
- **remote 调用通道**：`SmartProviderRemote.probeModels`（`lib/remote.js:286-297`）+ 客户端 `runProbe`（`client.js:2851`）+ strict codec（`client.js:300-315,456-480`）。
- **结果缓存与持久化**：`probe-cache.jsonl`（`lib/probe.js:57-86`）+ 冷启动回放（`lib/health-persistence.js:280`）+ UI 的 `probeVerdicts` 内存态（`client.js:2777`）。
- **展示组件**：Overview 的 pill 墙 / AccountsTab 表格（`client.js:1056-1062,1640-1645`）、`AccountHealthPanel`（`client.js:2195-2211`）、`S.table/S.pill` 样式（`client.js:717-732`）。

### 需要新增
- **"分组判定规则"**：探到 `free`/`metered`/`unknown` 后，如何映射成"这台机器属于哪个本地模型分组"——**目前完全缺失**。
- **"分组结果"的持久化和数据结构**：现有缓存按 `(provider, model)`，不是按"机器/账户/分组"；若按机器维度存，需要新的 key 与存储。
- **"每个机器挑一个免费模型"的选择逻辑**：现有 `maybeFreeModels` 是全目录扁平列表，未按 group 聚合、也未做"每机器选一个"。

### 实现路径（从最轻到最重）

**路径 A（最轻，纯 UI + 现有 probe）：客户端复用 `probeModels`，按 group 各挑 1 个候选探一次，在 `probeVerdicts` 上直接标注分组**
- 改动：`client.js` 新增一个聚合函数（按 `pi.models[i].group` 分组，从 `maybeFreeModels` 里每组取 1 个）→ 复用 `runProbe(candidates)`（`2851`）→ 用现有的 `probeVerdicts[group/model]`（`2777`）作为"分组判定结果"，在 Overview/AccountsTab 增一列或 pill 展示。
- 影响面：**仅 `client.js`（+ 7 语 i18n 字典内的 key）**；不碰 Host、`@Remote`、schema、缓存文件。
- 前提/限制：判定规则只能是"该组代表模型探到 free 就标免费组"，且结果不跨会话持久化（`probeVerdicts` 是 React state，reload 后靠 Host 缓存 `peek` 才能恢复，但客户端没有 peek 通道，见 `lib/remote.js:319-337` 无对应方法）。

**路径 B（中等，加 Host 通道）：新增 `@Remote` 方法 `modelGroupProbe()`（或扩展 `probeModels` 返回值），Host 侧按 group 聚合 + 返回可持久化的分组结论**
- 改动：`lib/probe.js` 增 `probeGroups(candidates, groups)` 或新纯函数把 verdict 映射成分组；`lib/remote.js:286-297` 增方法并在 marker（`:323-337`）注册；`client.js` 增 contribution/codec（对照 `456-480`）；`index.js:302` 无需大改（复用 adapter.probe）。
- 影响面：`lib/probe.js`、`lib/remote.js`、`client.js`、`index.js`（可选）、测试（新增 codec 与分组映射单测）。`docs/现状调研报告-模型定位只读展示.md:204` 指出新增 `@Remote` 会牵动 contribution + strict codec 三处，务必同步。
- 前提：判定规则已定义；可复用 `probe-cache.jsonl` 持久化（按 `(provider,model)` 存 verdict，分组在读取时现算，无需新存储）。

**路径 C（最重，新数据域）：新建"本地模型分组"推导 + 持久化模块，作为独立产品能力**
- 改动：新增 `lib/model-group.js`（按机器/账户/通道聚合模型集合 + 免费探测结果 → 分组标签），新存储（如 `model-groups.jsonl` 或写进 L1 registry 的新字段），`index.js` 装配与冷启动 hydrate（`lib/health-persistence.js` 扩展），`lib/remote.js` 新 `@Remote` 方法，`client.js` 新展示块/表（可复用 `S.table` 与 `AccountHealthPanel` 范式），i18n 7 语，`README.md`/`docs/` 更新。
- 影响面：最大，跨 Host/客户端/文档/测试；仅在"分组"是独立、需要长期保存且跨 reload 可见的产品概念时才值得。

## 5. 关键不确定点与需向用户澄清的问题

1. **"判断分组"的判定标准是什么？（最核心）** 探到 `free` / `metered` / `unknown` 分别应判成哪个"本地模型分组"？是按"整台机器所有模型都免费 → 免费机"，还是"任一个免费 → 含免费组"，还是按模型能力（与 `derivePosition` 混同）？现有代码没有任何映射规则。
2. **"每台机器"的边界是什么？** 是一个 provider/route（`group`，如 `x-opencode-free`）、一个 `accounts[]` 条目、还是一台物理机上的所有 provider？现有 `group` 来自 modelCatalog；`accounts[]` 与 `ranking` 在 `client.js` 另行维护（`accountDeclaredOf`，`:845-860`）。两者不是一回事。
3. **"如果有免费模型，选用一个"的挑选顺序与可靠性**：按 `freeSignal` 的哪个等级入选（weak 名字含 free 就够吗）？若机器里没有"确认免费"的模型（只有 weak），是否仍然探？`probeVerdict==='unknown'` 时分组标什么（现有"不能挡"规则意味着 unknown 不否定弱信号）。
4. **探测结果如何持久化 / 与现有 7 天 TTL 缓存的关系**：路径 A 的 `probeVerdicts` 不跨 reload；`probe-cache.jsonl` 已有 7 天 TTL（`lib/probe.js:38`），分组结论是复用它现算，还是新存一份？新存的话存哪里、与 `invalidate()`（`index.js:387/391`）如何联动？
5. **与"逐台定位表"的关系**：design-scout 的"逐台定位表"指 `derivePosition()` 的能力定位标签展示（`docs/现状调研报告-模型定位只读展示.md`），数据来自 catalog 能力字段；本思路的探测分组来自**实测计费**，是两个正交维度。需要澄清：是否要在同一张表里并列两列（定位标签 + 免费探测分组），还是做成两个独立区块？两者是否复用同一次探测过程？（**判断：目前不能复用同一探测**——定位表不依赖、也不产生 probe 结果；只有"展示位置/组件"可复用。）
6. **探测的花费与频率边界**：现有 `ranking.probeEnabled`（`client.js:1483-1489`）默认开启、`maxPerCall=3`；"每台机器探一次"意味着机器数 × 1 次，若机器多是否需要新的 cap / 用户开关？付费模型最多 1 token（`client.js:3233`）用户是否接受？
7. **失败与降级**：免费模型不可用 / 探测服务未挂载（`client.js:2865` 的 `probeDiag` 文案）/ 模型名变化（`invalidate` 触发重探）时，分组如何展示？现有纪律是"读不到就说读不到、不造假表"（`client.js:1495,1519`），分组空态也应遵循。
8. **是否复用 `provider-topology.js` 的 AGGREGATOR/DIRECT 分组**：用户说的"分组"是否其实是"这台机器是否内部池化账户"（`lib/provider-topology.js:115`）？若是，该模块已有结构化判定（不能用名字判断），与免费模型探测无关，需要重新界定需求。

## 6. 与「逐台定位表」的关系判断（结论）

- **数据维度不同**：逐台定位表 = catalog 能力 → `derivePosition()` tags（reasoning/longctx/vision/tool…，`lib/routing.js:205-224`）；本思路 = 实测计费/免费 → 分组标签。**同一台模型可以有"定位=reasoning"且"计费分组=免费"，两者独立。**
- **探测不可共用**：现有 probe 只产出 `free/metered/unknown`（`lib/probe.js:88-103`），不产出能力标签；`derivePosition()` 只读 catalog 字段，从不读 probe 结果。要让一次探测同时服务两者，需要给 probe 加"顺便探测能力"的新语义（例如用不同 prompt 测推理/视觉），这超出当前框架，属于路径 C 级别。
- **可共用的是"展示层"**：`pi.models`（`client.js:2959`）提供模型清单，表格样式与只读纪律（`S.table`、`docs/现状调研报告-模型定位只读展示.md:149`）可复用；`probeVerdicts` 已按 `group/model` 索引（`client.js:938,1057,1644`），可直接作为新表的一列数据源。
- **建议**：设计阶段先明确 §5 的判定标准，再决定是"在同一张逐台表里加一列免费探测分组"（路径 A，最省），还是"独立分组能力"（路径 B/C）。
