### 2.1 后端逐台模型能力字段（**已存在**）

## 6.「自动推导定位」所需输入是否具备 —— 结论

**分两层看，答案是「后端具备、前端不具备」：**

| 环节 | 是否具备 | 证据 |
|---|---|---|
| 逐台能力字段（`reasoning`/`contextWindow`/`input`/`tool`）在 Host 侧存在 | ✅ 具备 | `lib/routing.js:201-214`；`index.js:341-353` `adapter.routes = routes`；`lib/adapter.js:399-421` |
| 自动推导算法（能力 → 定位 tags） | ✅ 已实现 | `lib/routing.js:205-224` `derivePosition()`，运行期已在用：`lib/adapter.js:658-672` |
| 手填覆盖通道 | ✅ 已实现 | `ranking.routing.positionOverrides`（`README.md:389`、`lib/routing.js:176-194`、`index.js:234-279`） |
| 任务识别四档规则（图片/工具/推理/长文本） | ✅ 已实现，且比 UI 文案更全（P0/P5/P6） | `lib/routing.js:126-173` |
| **设置页读取逐台定位结果** | ❌ 确实没有 | `client.js` 无 `derivePosition` 调用；`pi.models` 仅 `{id,name,group}`（`2952-2961`）；`@Remote` 无对应方法（`lib/remote.js:319-337`）；`1519-1528` 只渲染静态文案 |
| **前端拿到逐台能力字段** | ❌ 没有 | 同上；`docs/两层智能路由设计.md:54` 明确把「`listModels()` 是否原样暴露这些字段」标为**未验证** |

因此，用户所说的「当前页面不读取逐台模型的定位结果」**属实**；而「自动推导定位」所需的**输入数据与算法在 Host 端已经现成可用**，缺的是：①把逐台能力 / 定位结果暴露到设置页的通道（新增 `@Remote` 方法，或让客户端从 `session.modelCatalog()` 读取能力字段后本地调用等价推导——但后者需先确认 catalog 字段真实存在）；②一个新的只读展示块（或把现有块从 `Advanced` 里提出来）。

## 7. 关键不确定点（需设计阶段决定 / 向用户澄清）

1. **需求意图**：用户写的是「这是只读说明，不是可编辑的表格」+「当前页面不读取逐台模型的定位结果」+「这个要想办法展示」——是要**把已有静态说明搬到更显眼的位置**，还是要**真正展示逐台模型的推导结果（真实数据只读表格）**？现有代码两者都没有后者，须澄清。
2. **`session.modelCatalog()` 是否带能力字段**：设计文档 `docs/两层智能路由设计.md:54` 明确标注未验证；当前客户端 `client.js:2957-2959` 直接丢弃了这些字段。若走客户端推导路线，需先用只读探针实测（本次任务未做）。
3. **通道选择**：新增 `@Remote` 方法（如 `modelPositions()`）会改动 `lib/remote.js` 的 marker（`319-337`）、客户端 contribution 声明（`client.js` 中 `makeCostContribution` 一带）与 strict codec；复用 `pi` 快照则不需要新通道但依赖 catalog 字段。两条路线的测试面不同。
4. **四档文案与实现不完全一致**：UI 只展示 P1–P4，代码还有 P0 显式 `+<tag>` / `requiredCapabilities`、P5 `purpose`、P6 `general`；另外 `tool` 档在 `derivePosition` 是「catalog `tool !== false` 即默认具备」，与设计文档 `1.2` 表「catalog 无字段 → 手填 / 默认 chat=yes」口径微妙不同。是否补齐说明需决定。
5. **展示档位范围**：用户提到四档，但产品定义有 7 档（`POSITION_TAGS`，含 `thrifty`/`swift`，且这两档永远不能自动推导，`README.md:406`）。是否展示完整 7 档并标注来源（auto / user / mixed）待定。
6. **阈值展示**：`longContextTokens` 默认 200000、可配置（`lib/routing.js:27,162-164`、`README.md:391`），文案里「内容超长」未带阈值；若展示规则，是否同时显示当前阈值（且该字段目前**不在设置页表单里**，仅 `applyPreset` 注释 `client.js:3068` 提到要保留）。
7. **手填入口**：用户说「个别模型可另外手填」，但设置页表单**完全没有** `positionOverrides` 控件（client.js 全文无该字符串用于表单），只有 Host 配置 / registry 文件两条路。新需求是否包含「提供手填入口」，还是继续仅作说明？
8. **i18n 覆盖**：`TASK_RULES` 中文硬编码（`client.js:588-593`），若做成正式展示需补齐 7 语；且 locale 字典在 `client.js` 内部而非 `locale/*.json`，容易改错地方。
9. **可见性与交互**：`Advanced` 的设计意图是隐藏高级项（`client.js:796-798`），但 `CostPillSettingsCard` 有「BX2 首屏可见」先例（`client.js:3108-3109`）。新块放折叠内还是首屏，涉及首屏信息密度与 Tab 草稿守卫（`2704-2720`）的影响。
