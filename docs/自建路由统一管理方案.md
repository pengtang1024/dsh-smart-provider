# 自建路由统一管理方案

> 注：本文档写于 2.2.0 之前，设置页 Tab 结构与行号为旧状态；现行实现见 README §一 与 DETAIL.md

> 状态：只读设计稿（task-37）。本轮**不改任何生产配置/代码、不重启 DSH**。
> 事实基线来自本机真实源码与配置，证据见 §10（含文件:行号）。
> 用户拍板原话：「看来自建路由还是有必要的」「先出自建路由方案吧，否则没法统一管理」——本文给的**是一个确定方案**，不是选择题。

## 0. 结论先行

**确定方案：中央自定义路由注册表（Custom Route Registry）——以 pi-ai `providers` 为唯一执行面，以 smart 插件为唯一编排面，一处声明、自动生成、自动校验、下游全部派生。**

一句话：

> catalog-absent 模型**只能**落在 pi-ai 的 `providers` dict（这是 schema 硬约束，绕不过）；所以"统一管理"不是再找第二个落点，而是**把这一个落点集中到一份声明源里，让 chains、配置页候选、价格表、子 agent 白名单全部由它自动生成**，从此每加一个模型 = **改 1 个文件 + 跑 1 条命令**。

三个关键决定（都基于硬事实，不是偏好）：

1. **承认 pi-ai `providers` 是唯一执行面。** `modelFields` schema 不接受 per-model `api/baseURL`（pi-ai `config.ts:332-350`）；`resolveRouteModels` 对 catalog-absent 模型强制要求 route 级 `api`+`baseURL`（`catalog.ts:918-925`）。想"不碰 providers"就等于重写 `PiAiAdapter`（需要复制 profiles resolver / resolveApiKey / auth / discovery 整套胶水），那是拿已验证的 390 行 SmartAdapter 去换一个更小的东西，收益为负。**唯一健康的落点就是 pi-ai providers 里一个独立、隔离的 route。**

2. **"上次给 opencode-go 加 api 弄坏 29 个模型"的教训，用"命名隔离 + 校验器"从结构上根除。** 每个 catalog-absent 厂家一个**独立 route**（约定 `x-` 前缀），只放它自己的模型；校验器强制"route 只含自己声明的模型、不碰 catalog route、不撞已有 route id"。覆盖协议的事不再可能发生。

3. **下游全部派生，消灭"第 5 个补丁点"。** 现在加一个模型要手改：① cordis.patch.yml 的 providers ② chains.js ③ client.js 候选常量 ④ pricing.json ⑤ allowedModels 白名单。方案后这 5 处**全部由声明源生成**，人工只碰声明源一处。

为什么不选另外两个候选（评估记录）：
- **候选2「smart 内置虚拟 route」**：不成立。smart 的 hop 最终必须落到 `ctx.llm.stream({provider})` 上，而 provider 必须是真实注册的 route；smart 自己造虚拟 route 仍要落到某个真实 adapter，等于要么重写 PiAiAdapter、要么动态改 pi-ai config（Cordis config 按插件 fiber 隔离，smart 改不了 pi-ai 的 namespace）。**技术上行不通，排除。**
- **候选1 的裸版本「只写个生成器」**：方向对但没解决"落点"问题；本方案吸收它的生成器/校验器，但把它锚定在"pi-ai providers 是唯一执行面"这个正确前提上，并补齐热更新与编排自动接线。

## 2. 确定方案：中央自定义路由注册表

### 2.1 架构图（文字版）

```
                        ┌─────────────────────────────────────────┐
   人工唯一编辑点  ───▶ │  声明源  custom-routes.yaml             │
                        │  (dsh-smart-provider/registry/)          │
                        │  routes:                                 │
                        │    - id: x-workbuddy                     │
                        │      protocol: openai-completions        │
                        │      baseURL: https://…/v1                │
                        │      credentialRef: <VENDOR>_API_KEY      │
                        │      tier: free                           │
                        │      models: [hy4-flash-free, …]          │
                        └──────────────┬────────────────────────────┘
                                       │  gen + validate（1 条命令）
                   ┌───────────────────┼────────────────────┬─────────────────┐
                   ▼                   ▼                    ▼                 ▼
        ┌──────────────────┐  ┌────────────────┐  ┌────────────────┐  ┌────────────────┐
        │ ① pi-ai          │  │ ② smart        │  │ ③ 配置页候选   │  │ ④ pricing.json │
        │   providers      │  │   chains       │  │  常量 (UI)     │  │  价格条目      │
        │   route 片段     │  │   hop (free→   │  │  MODEL 下拉    │  │  (free=0)      │
        │  (唯一执行面)    │  │    paid)       │  │                │  │                │
        └────────┬─────────┘  └────────┬───────┘  └────────────────┘  └────────────────┘
                 │                     │
                 │ volatile-update     │ reconfigure (已有机制)
                 ▼                     ▼
        ┌──────────────────────────────────────────────────────────────┐
        │  PiAiAdapter (pi-ai 注册 x-* route)                          │
        │  SmartAdapter (registerAdapter(['smart']) —— 唯一注册源)     │
        │    stream(): resolveChain → AccountPool.plan → 逐 hop 尝试   │
        │    QUOTA/402 → cooldown → 下一 hop（免费→付费）              │
        └──────────────────────────────────────────────────────────────┘
```

三个面各司其职，边界清晰：

- **声明面（人工）**：`custom-routes.yaml`，唯一需要手改的文件。业务语言，不含密钥明文。
- **执行面（pi-ai）**：`x-*` 独立 route，由 PiAiAdapter 注册；这是 catalog-absent 模型唯一能出字的落点（F2/F3）。
- **编排面（smart）**：chains/账号池/冷却/成本，全部已有；只把 `x-*` hop 按 tier 接进来。

### 2.2 命名与隔离约定

- 自定义 route id 一律 `x-<vendor>` 前缀（如 `x-workbuddy`、`x-acme-gateway`）。`x-` 不在 pi-ai catalog id 集合里，也不等于 `smart`/`opencode-go`/`xiaomi-token-plan-cn` 等已有 route → 从命名上杜绝 F9 的 DUPLICATE_ADAPTER。
- 一个 route 只含**自己厂家**的模型（F4 的根除手段）。校验器硬性检查：声明的 model id 不得出现在任何非本 route 的已有模型清单里。
- `tier` 三值：`free`（免费/试用，自动排链首）/ `standard`（付费，兜底）/ `disabled`（登记但停用）。tier 只影响编排顺序，不影响是否注册 route。

## 3. 数据结构与配置格式（key 已打码）

### 3.1 声明源 `custom-routes.yaml`（人工唯一编辑点）

```yaml
# dsh-smart-provider/registry/custom-routes.yaml
# 所有 catalog-absent 模型的唯一权威声明。新增模型只改这里。
# credentialRef 是凭据"引用名"，不是密钥明文；密钥仍由 DSH credentials 服务保管（F7）。
version: 1
routes:
  - id: x-workbuddy                    # 必须 x- 前缀；不得撞 catalog / smart / 已有 route
    displayName: WorkBuddy Free
    protocol: openai-completions       # 仅 4 选 1（F8）
    baseURL: https://api.<VENDOR>.example/v1   # 打码；写到 /v1，见 §4 的 baseURL 对照
    credentialRef: WORKBUDDY_API_KEY   # 打码：实际填已注册凭据引用名
    tier: free                         # free → 自动进 auto 链首
    models:
      - id: hy4-flash-free
        name: HY4 Flash (Free)
        contextWindow: 960000
        maxTokens: 64000
        input: [text, image]
      - id: hy4-flash                  # 同厂付费孪生：不同 id，避免 dedupe 吞掉（§5 坑）
        name: HY4 Flash
        contextWindow: 960000
        maxTokens: 64000
        input: [text, image]
        tier: standard                 # 模型级可覆盖 route 的 tier

  - id: x-acme-gateway
    displayName: ACME Gateway
    protocol: anthropic-messages
    baseURL: https://gateway.<VENDOR>.example   # anthropic 自带 /v1，别再写 /v1（防 405）
    credentialRef: ACME_GATEWAY_API_KEY         # 打码
    tier: standard
    models:
      - id: acme-coder-v9
        name: ACME Coder V9
        contextWindow: 200000
        maxTokens: 32000
        input: [text]
```

### 3.2 生成物 A：`llm-pi-ai.providers` route 片段（唯一执行面）

```json
{
  "x-workbuddy": {
    "displayName": "WorkBuddy Free",
    "apiKeyEnv": "WORKBUDDY_API_KEY",
    "api": "openai-completions",
    "baseURL": "https://api.<VENDOR>.example/v1",
    "models": [
      { "id": "hy4-flash-free", "name": "HY4 Flash (Free)", "contextWindow": 960000, "maxTokens": 64000, "input": ["text", "image"] },
      { "id": "hy4-flash",      "name": "HY4 Flash",        "contextWindow": 960000, "maxTokens": 64000, "input": ["text", "image"] }
    ]
  }
}
```

字段全部对齐 pi-ai `profile` schema（`config.ts:355-383`）：route 级 `api`/`baseURL`/`apiKeyEnv`/`models`，模型级只有 `id/name/contextWindow/maxTokens/input`（F2）。`apiKeyEnv` 是引用名（F7）。

### 3.3 生成物 B：smart chains（编排自动接线）

```json
{
  "auto": [
    { "provider": "x-workbuddy", "model": "hy4-flash-free" },
    { "provider": "x-workbuddy", "model": "hy4-flash" },
    { "provider": "opencode-go", "model": "deepseek-v4.1-flash" },
    { "provider": "opencode-go", "model": "glm-5.3-flash" }
  ],
  "hy4-flash-free": [{ "provider": "x-workbuddy", "model": "hy4-flash-free" }]
}
```

规则：所有 `tier: free` 模型按声明顺序排在 auto 链首，其后是原有付费链；`tier: standard` 的自定义模型追加到付费段尾部（或按 affordability 插入，由声明里的 `order` 控制）。显式模型键（如 `hy4-flash-free`）自动生成直达 hop。

### 3.4 生成物 C/D：UI 候选 + pricing 条目

- C：把自定义 model id 注入 `client.js` 的 `MODELS` 候选数组（由生成器写入常量区，不再手改）。
- D：`pricing.json` 追加条目；`tier: free` 的模型 `input/output/cacheRead/cacheWrite` 全填 `0`，成本计量能验证"确实走了免费路由"。

## 4. 接入一个新模型的完整步骤（可复制）

> 场景：发现一个新厂家/新模型要用，从"知道它"到"配好能用"。

1. **拿三件事**：厂家 endpoint 的 `baseURL`、wire 协议（只能 4 选 1，F8）、凭据引用名（先确认凭据已通过 DSH 凭据服务/设置页登记）。
2. **在 `custom-routes.yaml` 加一段声明**：新厂家就加一个 `x-<vendor>` route；同一厂家加模型就在已有 route 的 `models` 下加一条 `id/name/contextWindow/maxTokens/input`，并设 `tier`。
3. **跑一条命令生成 + 校验**：
   ```bash
   node dsh-smart-provider/scripts/gen-custom-routes.mjs --write   # 生成 A/B/C/D
   node dsh-smart-provider/scripts/validate-custom-routes.mjs      # 校验，失败非零退出
   ```
4. **看校验输出**：校验器逐项报——route id 唯一且不撞现有/catalog/smart；protocol ∈ 4 种；baseURL 与 protocol 匹配（防 `/v1/v1` 405，详见下方对照）；凭据引用存在；model id 全局唯一且不被别的 route 声明；每个 route 只含自己的模型（防 F4）。
5. **热更新生效**：pi-ai providers 是 volatile（F6），配置变更经 `loader/volatile-update` 原子 replace；smart 的 chains/accounts 也在同一事件里 `reconfigure`（`index.js:109-128`）。**无需重启**。
6. **出字探针 + 成本探针**：用该模型发一条最小请求，确认 ① 能出字 ② hopIndex 指向 `x-<vendor>` ③ `usage.cost=0`（免费模型）。可复用现有 `scripts/query-cost.mjs` 与 `smart-health`/`smart-status` 命令。
7. **回滚失败时**：只撤掉第 2 步加的那段声明，重跑第 3 步（带 `--write`），chains/pricing/UI 自动回退；或按 §9 的回滚预案。

**协议 → baseURL 对照（防 405，接入必查，F8）**：

| protocol | baseURL 写法 | 上游 SDK 会拼 |
|---|---|---|
| `openai-completions` | 写到 `/v1` | `/chat/completions` |
| `openai-responses` | 写到 `/v1` | `/responses` |
| `anthropic-messages` | **不带** `/v1` | 自带 `/v1/messages`（写 `/v1` 会变 `/v1/v1/messages` → 405，已实证） |
| `google-generative-ai` | 通常不带版本段 | SDK 自带路径 |

校验器按此表做静态检查；仍建议第 6 步用真实探针兜底。

## 5. 免费优先怎么自然实现

省钱不是额外加的开关，而是**现有 SmartAdapter 能力 + 声明源 tier 排序**的自然结果：

1. **链首免费**：生成器把所有 `tier: free` 模型按声明顺序放在 `auto` 链首（§3.3）。`resolveChain('auto')`（`chains.js:71-84`）第一步就指向免费 route。
2. **额度耗尽自动 fallback 付费**：
   - 免费额度用尽时上游返回 `402` / quota，被 `normalizeFailure` 归一为 `QUOTA`（`adapter.js:53-77`）。
   - `QUOTA` ∈ `SWITCHABLE_CODES`（`chains.js:31-37`）→ `#setCooldown` 给该账号打冷却（默认 30min，`adapter.js:34-39,401-407`）。
   - `stream()`（`adapter.js:319-385`）跳到下一 attempt = 链里的付费 hop。
   - 关键前提成立：免费 hop 在**输出任何 token 前**就 402，`emitted=false` → 允许 fallback；一旦已出字（emitted=true）则提交不回退（establishment-only，`adapter.js:352-357`）。这正是想要的语义。
3. **同模型多账号轮换**：若免费模型配了多个 key（多 route 或 accounts），账号池先轮换所有健康账号（`account-pool.js:145-191`）再换模型，把免费额度吃满。
4. **省钱可验证**：免费模型在 pricing.json 里 price=0 → cost meter 记录 cost=0；`query-cost.mjs --by-account` 能证明实际走的是免费路由，不是事后嘴上说省钱。
5. **外层不放大烧钱**：smart route 已配 `providerRetryPolicy` = `maxRetries:0`（`adapter.js:21-26,168-172`），避免"整链失败后外层再重试 5 次"的乘性放大（`方案盲点审查.md:15,79`）。

**一个必须写明的坑**：`account-pool.js:156-159` 的 `seenModels` 按 `model` 去重。若 auto 链首和 fallback 是**同一个 model id**（如免费/付费都用 `hy4-flash`），第二条 hop 会被吞掉，fallback 失效。规避：声明源文件里免费/付费用**不同 id**（如 `hy4-flash-free` vs `hy4-flash`，见 §3.1），或走"同一 model 多 account"路径（此时按 account 轮换，不依赖 hop 切换）。校验器对"auto 链中重复 model id"告警。

## 6. 配置页联动（改不改、改多少）

**结论：小白视图零改动；只在"详细设置"折叠区加一个只读的"已接入自定义模型"清单，新增模型不走配置页。**

- 现状：Smart 设置四 Tab（总览/切换链/账号池/成本健康，`client.js:559-562`），所有编辑都是下拉/按钮，**没有 JSON 输入框**（`client.js:181-190` Advanced 默认折叠，`:248-313` ChainsTab 结构化编辑）。小白看不到 `api/baseURL/protocol/credentialRef` 这类技术字段。
- 方案后：
  - **新增模型不进配置页**——技术字段只由 `custom-routes.yaml` 维护，配置页永不暴露 `api/baseURL`（避免小白误填 `/v1/v1` 或贴明文 key）。
  - **只做一件事**：把生成器产出的 model id 自动并入 `client.js` 的 `MODELS` 候选常量（生成物 C），让用户在 ChainsTab 里能选到新模型。这一步是生成写入，不是手改。
  - **可选增强**（P2，非首期）：在折叠区加只读清单"已接入的自定义模型（由注册表管理）"，展示 model id + tier + 是否免费，配一行"要新增模型请联系管理/改注册表"。纯展示，零编辑。
- 改动量：**首期配置页代码改动 ≈ 0**（只有生成器写常量）；可选增强 ≈ 1 个只读卡片。`DYNAMIC` 候选也可改为从 `smart-status` 命令读取已注册 model id，进一步免去常量生成——二选一，首期走常量更简单。

## 7. 与 `llm-pi-ai.providers` 的关系 + DUPLICATE_ADAPTER

- **是"在 pi-ai providers 里加 `x-*` route"，不是"另起注册表"。** 理由见 §0 决定 1（F2/F3 硬约束）。这是唯一能让 catalog-absent 模型出字的落点。
- **另一个注册表是 smart 的编排表**（chains/accounts），它引用 `x-*` route 作为 hop，但**不注册** route。
- **DUPLICATE_ADAPTER 根除**（F9）：
  - `smart` 只通过 `registerAdapter(['smart'])` 注册（`index.js:86`），**绝不**在 `llm-pi-ai.providers` 里加 smart 块（`cordis.patch.yml:3-6` 已明确此约束）。
  - `x-*` route 只在 pi-ai providers 里由 PiAiAdapter 注册；smart 不 registerAdapter 它们。
  - 两张注册表：`registerAdapter` → `this.adapters`；`registerConfigurableProviders` → `this.directory`（`两交付物补救方案.md:6`）。二者同名不冲突；真正会炸的是**同名 route 被两个 adapter 各注册一次**——`x-` 前缀 + smart 唯一注册源使这事结构上不可能。
  - 校验器再加一道闸：`x-*` id 若与任何 catalog id / 已有 route 重名 → 直接报错拒绝生成。

## 8. 六个验收问题逐条回答

**Q1 新模型/新厂家接入路径（几步、改几个文件、有无校验）**
→ 改 1 个文件（`custom-routes.yaml`）+ 跑 1 条命令（gen+validate）+ 1 次出字/成本探针（§4）。校验器覆盖命名/协议/baseURL/凭据/唯一性/隔离 6 类（§4 第 4 步）。

**Q2 catalog-absent 模型怎么安全承载（不破坏现有 29 模型）**
→ 独立 `x-*` route，route 级 api/baseURL，只含自己的模型；校验器强制"不碰 catalog route、不撞已有 id、每 route 只含自己模型"。F4 的覆盖事故从结构上不可能复发。

**Q3 省钱怎么落地（auto 首免费 + 耗尽 fallback 付费）**
→ tier 排序让 free 模型成 auto 链首；402/QUOTA 触发 cooldown + 下一 hop（付费），establishment-only 保证已出字不回退；外层 maxRetries=0 防放大；pricing=0 + cost meter 可验证（§5）。

**Q4 配置页联动（要不要改、小白会不会见到技术字段）**
→ 首期配置页代码 0 改动（生成器写候选常量）；小白视图永不暴露 api/baseURL/protocol/key；可选只读清单（§6）。

**Q5 与 llm-pi-ai.providers 关系 / DUPLICATE_ADAPTER**
→ 在 providers 里加 `x-*` route（唯一执行面）；smart 只编排不注册；smart 唯一 registerAdapter 源 + `x-` 前缀 + 校验器，DUPLICATE_ADAPTER 结构上不可能（§7）。

**Q6 维护成本（一次声明 vs 多处手改）**
→ **一次声明**。旧路径 5 处手改（providers/chains/client/pricing/allowedModels）全部由声明源派生。禁止在派生文件里手改（生成器下次会覆盖）；如需定制，改声明源。
