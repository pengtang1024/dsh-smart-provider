# Интеллектуальная маршрутизация моделей (Smart Provider)

Мета-провайдер, зарегистрированный как маршрут `smart`. Сам он не вызывает никаких API больших моделей — вместо этого он по очереди пробует **уже настроенные вами маршруты провайдеров DSH** и выбирает первый, который ответил. Это **универсальный интеллектуальный маршрутизатор**, а не инструмент экономии: четыре цели — экономия средств / высокая производительность / широкие возможности / комбинированный (интеллектуальный) подход. В коде по умолчанию задана нейтральная позиция (сбалансированные веса .25); «приоритет экономии» — это осознанный выбор конфигурации пользователя.

**Текущее состояние: плагин установлен и включён, назначен моделью по умолчанию, статус плагина ACTIVE.** Интеллектуальная маршрутизация действует по умолчанию; цепочки экономии, реальная запись и чтение на странице настроек, P1 (адаптация к ресурсам / нейтральные настройки по умолчанию / динамические цепочки) и P2 (двухуровневая интеллектуальная маршрутизация, по умолчанию отключена) реализованы и независимо проверены. Порядок маршрутов определяется вашей актуальной реестровой базой и конфигурацией; этот документ не фиксирует конкретные числа.

## Возможности

- **Интеллектуальная маршрутизация включена по умолчанию.** `smart/auto` — модель по умолчанию; выбор маршрута и откат проверены в реальных сессиях. Встроенный список цепочек намеренно пуст; без конфигурации `discoverAutoChain()` создаёт из актуального реестра DSH нейтральную цепочку `auto` (сортировка по имени провайдера/модели, без жёстко встроенных моделей конкретных пользователей).
- **Цепочка экономии (необязательная, не по умолчанию).** Бесплатный маршрут `x-opencode-free` (`hy4-flash-free`) автоматически ставится в начало цепочки благодаря `tier: free` в `registry/custom-routes.user.yaml`; в реальном журнале расходов каждая запись этого маршрута имеет `estimated_cost_usd=0` (проверено 213+ записей); при ошибках 402/квоты происходит откат на платный маршрут.
- **Пул аккаунтов (несколько аккаунтов = пул).** Модель и аккаунт — два независимых измерения. Каждый переход цепочки сопоставляет модель с пулом аккаунтов (`{id, provider(маршрут), credentialRef, models[]}`); сначала выбираются исправные аккаунты на маршруте этого перехода, затем — менее использованные; перед переходом к следующей модели перебираются все исправные аккаунты текущей модели. Поскольку DSH связывает с каждым маршрутом только один ключ, второй аккаунт — это второй маршрут провайдера. Массив `accounts` необязателен; без конфигурации поведение побайтово совпадает со старой версией.
- **Задержка на уровне аккаунта.** Ключ задержки — `accountId`, а не `provider/model`. Ошибка 402 или квоты у одного аккаунта замораживает только его; другие аккаунты той же модели продолжают обслуживать запросы.
- **Откат только до установления ответа.** Как только передан любой блок текста, рассуждений или вызова инструмента, ответ считается зафиксированным — уже показанные токены не отзываются; `ABORTED` никогда не вызывает откат.
- **Журнал сессий для каждой попытки.** Каждая попытка записывается в виде игнорируемой плагином записи `plugin:dsh-smart-provider/hop-selected` с полезной нагрузкой
  `{event:'smart/hop-selected', hopIndex, provider, model, accountId, failureCode, at}`.
  Это безопасный способ расширения за пределами репозитория для `smart/hop-selected`: прямая отправка неизвестного типа события заставила бы систему сохранения сессий отклонить восстановление журнала.
- **Ранжирование аккаунтов (P1, по умолчанию отключено).** Оценка по четырём факторам: стоимость / скорость / уровень / нагрузка; `balanced` — нейтральные настройки по умолчанию (.25), `cost-first` и подобные — явные варианты; при отключении сохраняется старое поведение (приоритет маршрута + меньше использованный).
- **Двухуровневая интеллектуальная маршрутизация (P2, по умолчанию отключена).** В `lib/routing.js` четыре чистые функции: классификация запроса, вывод меток позиции модели, выбор слоя кандидатов и разрешение предустановок. Активируется только при `ranking.routing.enabled=true`; без конфигурации код побайтово идёт по legacy-пути. Восемь предустановок стратегий: `balanced` / `cost-first` / `speed-first` / `reasoning-first` / `longctx-first` / `vision-first` / `legacy` / `custom`. Метки позиций выводятся автоматически из каталога моделей (reasoning / contextWindow≥200000 / входные данные содержат image / tool!==false / общая), их можно вручную исправить через `positionOverrides`; ошибки конфигурации лишь выводят WARN и откатываются к legacy, не вызывая сбой.
- **Вкладка «Стоимость / Состояние» с реальным журналом.** Страница стоимости читает через сервис `@Remote` `smartProvider.cost()` (`lib/remote.js`) агрегацию `lib/cost-stats.js` по реальному `cost.jsonl` (всего расходов / бесплатно / платно / ошибки / по провайдерам) — это не оценочные заглушки; на странице настроек также показаны реальные провайдеры/модели и имена учётных данных из pi-ai.

## Способы настройки

`chains`, `accounts`, `ranking` и `ranking.routing` — volatil-конфигурации; изменения на странице настроек вступают в силу сразу, без перезапуска. Конфигурация routing вложена в `ranking.routing` (schema.js:62-67), поля: `enabled` / `strategy` / `tierPolicy` / `weights` / `positionOverrides` / `tierLimit` / `longContextTokens` / `dynamicAuto`. Без конфигурации этот путь кода вообще не выполняется; явный ключ `chains` и `*` всегда имеют приоритет над `dynamicAuto`, поэтому старые конфигурации не меняются неожиданным образом. Каждый элемент пула аккаунтов `accounts` имеет вид `{id, provider, credentialRef, models[]}`; при отсутствии конфигурации работает старый режим «на переход». Собственные маршруты объявляются только в `registry/custom-routes.user.yaml` (`credentialRef` содержит исключительно имя ссылки, никогда не открытый ключ).

Подробное обоснование приведено в трёх документах родительского рабочего каталога: `meta-provider-设计方案.md`, `多账号池设计方案.md`, `方案盲点审查.md`.

## Краткая справка (второстепенная)

Мета-провайдер, зарегистрированный как маршрут `smart`, сейчас **установлен и включён** и назначен моделью по умолчанию. Это универсальный интеллектуальный маршрутизатор (стоимость / скорость / возможности / комбинированный), в коде нейтральный по умолчанию; приоритет экономии — включаемая пользователем конфигурация. Проверено: `smart/auto` в реальных сессиях, бесплатный первый переход `x-opencode-free` (cost=0, 213+ реальных строк журнала) с откатом 402→платный, страница настроек с реальными ресурсами pi-ai и вкладкой стоимости с журналом через `@Remote`, P1-адаптация ресурсов и включаемый P2-двухуровневый маршрутизатор (`ranking.routing.enabled=true`, 8 предустановок, побайтовый legacy при отключении). Полную конфигурацию и команды проверки см. в README пакета.
