## 一句话根因

账号池表格使用 `width:100%` 的**自动表格布局（auto table layout）**，没有任何列宽/最小宽度约束；最长的账号名列被显式设为 `overflowWrap:'anywhere'`（`client.js:2193`），浏览器在分配列宽时把它当作「可以无限折行消化」的列而压缩它，但末列「成功 / 失败」同样没有任何 `white-space`/`minWidth` 保护，表头文案本身含空格和斜杠（`client.js:3268`：`'成功 / 失败'`），于是末列被挤窄后表头在可断点处折成两行、内容溢出被容器右边界截断。

## 2. 表格布局 / 列宽 / 换行的样式代码

### 2.1 样式对象 `S` 的定义位置

`S` 定义于 `client.js:662`–`777`（注释 `// ---- styles: only --dsw-alias-* tokens` 在 `client.js:661`）。表格相关样式全部在 `S` 内，是**内联 style 对象**（通过 `style: S.xxx` 传给 `h()`），没有独立 CSS 文件。

### 2.2 与表格直接相关的样式定义（关键证据）

| 样式 | 位置 | 定义 | 与问题的关系 |
|---|---|---|---|
| `S.table` | `client.js:723` | `{ width: '100%', borderCollapse: 'collapse', fontSize: 12 }` | **没有 `tableLayout:'fixed'`** → auto layout，列宽由浏览器按内容自动分配；没有列宽契约 |
| `S.th` | `client.js:724` | `{ textAlign:'left', borderBottom:..., padding:'8px', color:..., background:..., fontWeight:500 }` | **没有 `whiteSpace:'nowrap'`、没有 `minWidth/width`** → 表头「成功 / 失败」在空格/斜杠处可折行 |
| `S.td` | `client.js:725` | `{ borderBottom:..., padding:'8px', verticalAlign:'top' }` | **没有 `whiteSpace:'nowrap'`、没有 `minWidth`** → 数字内容可在空格处断行、溢出无保护 |
| `idCell` | `client.js:2193` | `{ ...S.td, overflowWrap:'anywhere' }` | 账号名列显式允许在任意字符处断行 → 浏览器认为该列可无限压缩，影响整体列宽分配 |

- 成本明细表 `client.js:1972`–`1973`：容器 `overflowX:'auto'`，table `width:100%; minWidth:720/540`，`th/td` 复用 `S.th/S.td` — 与账号池表同样无列宽保护。

## 3. 问题根因分析

### 3.1 为什么「成功 / 失败」列被挤窄

1. `S.table` = `width:100%` + `borderCollapse:collapse` + 无 `tableLayout:fixed`（`client.js:723`）→ 采用 CSS 自动表格布局，浏览器按「最小内容宽度/最大内容宽度」分配列宽，没有稳定的列宽契约。
2. 第一列账号名列显式 `overflowWrap:'anywhere'`（`client.js:2193`），内容又包含长 ID `x-opencode-free/hy4-flash-free` + 第二行 provider（`client.js:2305`–`2310`）+ 「（自动派生）」标签（`client.js:2308`）。auto layout 会把该列视为「最小内容宽度接近 0」的可压缩列，从而把宽度让给其它列。
3. 但剩余三列同样没有任何 `minWidth`/`nowrap`（`S.th` `client.js:724`、`S.td` `client.js:725`），状态列和资费列的中文文本也可折行；四列都在竞争有限宽度，浏览器最终按内容折行结果分配，导致末列得不到足够宽度。
4. 唯一的总下限 `minWidth:560`（`client.js:2277`）在 588px 截图下与容器宽度接近：外层 `S.card` padding 14（`client.js:673`–`677`）左右共 28px，内容区约 560px 左右，处于「刚好够/刚好不够」的临界，表很容易被压到接近 560px 而不是稳定触发横向滚动。

### 3.2 为什么表头换行

- 表头文案 `health.samples` 是 `'成功 / 失败'`（`client.js:3268`），中间有空格和斜杠，都是合法断行点；`S.th`（`client.js:724`）没有 `whiteSpace:'nowrap'`，因此末列一窄就折成「成功 / 失」+「败」两行，与截图一致。

### 3.3 为什么内容被裁切

- 末列内容由 `samplesText`（`client.js:2168`–`2171`）生成 `` `${ok} / ${fail}` ``（如 `10782 / 237`）；`S.td`（`client.js:725`）无 `nowrap`/`overflow` 保护，数字串会在空格处断行，或在列过窄时溢出单元格。
- 外层容器设了 `overflowX:'auto'`（`client.js:2276`）：溢出的右侧内容会被容器裁掉，需要横向滚动才能看到——截图里 `10782 / 2…` 顶到右边界正好符合「溢出被容器边界裁切」的表现。
- **不确定**：代码里没有 `textOverflow:'ellipsis'`，截图描述里的 `…` 更可能是被裁掉的数字残段或描述者的省略记法，不能断定浏览器真的渲染了省略号。

## 5. 最小修复方向（候选，按推荐度排序；均未实施）

### 候选 A（推荐）：只给末列 th/td 加 nowrap + 适度提高表格 minWidth

- 改动点：`client.js:2282`、`client.js:2319` 两处 `style` 改为 `{ ...S.th, whiteSpace:'nowrap' }` / `{ ...S.td, whiteSpace:'nowrap' }`；`client.js:2277` 的 `minWidth` 从 560 提到能容纳四列内容的值（例如 620–680，需实测）。
- 效果：表头不再折行，数字不再断行/溢出；容器横向滚动成为兜底。
- 影响面：**最小**。只动账号池表格 3 行，不改共享 `S.th/S.td`，成本表与路由表完全不受影响。
- 代价：窄屏下用户需横向滚动看到末列完整内容。

### 候选 B：用 `<colgroup>` / 逐列 width + `tableLayout:'fixed'`

- 改动点：`client.js:2277` 给 table 加 `tableLayout:'fixed'`，并在 `client.js:2278` 之前插入 `<colgroup>` 给四列设百分比或 px 宽度；同步调整 `idCell` 的 `overflowWrap`。
- 效果：列宽完全可控，不再随内容漂移。
- 影响面：**较大**。fixed layout 下所有列都要重新设计宽度；账号列仍需保留断行策略；小屏可能需要重新考虑 minWidth 与滚动。

### 候选 C：只调大 minWidth，允许横向滚动

- 改动点：仅 `client.js:2277` 的 `minWidth:560` 改为更大值（如 720）。
- 效果：四列获得更宽松空间，末列不再被挤；超出容器时滚动。
- 影响面：**最小（1 个数字）**，但 auto layout 下列宽仍随内容漂移，不保证末列一定不再折行——**单独使用不稳妥**，建议与 A 组合。

### 不建议：全局给 `S.th/S.td` 加 `whiteSpace:'nowrap'`

- 位置：`client.js:724`–`725`。会影响成本明细表（`client.js:1972`）与路由表（`client.js:2330`），长 provider/model 文本不再断行，可能造成更大范围溢出。

## 6. 关键不确定点

1. **无原始截图文件**：本 agent 只拿到文字描述，无法核对真实渲染细节（滚动条是否存在、`…` 是否为真实省略号、各列实际像素宽度）。
2. **未做浏览器实测**：588px 是截图尺寸，不一定等于设置面板内容区实际宽度；外层 `S.card` padding 28px、`minWidth:560` 与容器宽度的临界关系需实测确认。
3. **宿主 CSS 不可见**：本插件只注入 button/summary 等少量 CSS（`client.js:3079`–`3088`），但 DSH 宿主（apps/web）可能给 table 注入默认样式，本调研无法覆盖宿主侧规则。
4. **`minWidth:560` 是否生效**：auto table layout 下 `min-width` 与 `width:100%` 的相互作用依赖浏览器实现，末列被挤的具体数值无法仅凭静态代码确定。
5. **多语言影响**：`health.samples` 在其他语言下文案长度不同（英文 `Success / failure`、`client.js:3451`；德文等），修复方案需考虑长文案语言下末列更宽的需求。
6. **未修改/未验证**：本报告不含任何代码改动，也未运行构建、测试或浏览器验证；所有修复方向均需在实现后由主 agent 实测验收。
